# Plan 01-03: Qdrant Go Client Init & Collection Setup

## Objective

Add `github.com/qdrant/go-client` to `go.mod`. Implement Qdrant client connection logic in a new `internal/rag` package. The connection must use exponential backoff (via `github.com/sethvargo/go-retry`) to handle startup order where Qdrant may take time to become healthy. Check if the `stockmind_knowledge` collection exists; if not, create it mathematically configured for 2048 dimensions and Cosine distance. Integrate this client startup into `cmd/main.go` so it errors/retries gracefully on server boot.

### Task 2: Implement Qdrant Client Init in `internal/rag`

<action>
Create package `rag` inside `internal/rag/`.
Create file `internal/rag/client.go`.

Implement `func InitQdrant(ctx context.Context, host, port string) (*qdrant.PointsClient, error)`:
1. `addr := fmt.Sprintf("%s:%s", host, port)`
2. Use `github.com/sethvargo/go-retry` with Fibonacci backoff (cap max 16s, total 5 retries):
   ```go
   b := retry.NewFibonacci(1 * time.Second)
   b = retry.WithMaxRetries(5, b)
   ```
3. Inside the retry block, attempt `grpc.NewClient(addr, grpc.WithTransportCredentials(insecure.NewCredentials()))`.
4. Create points client `qdrant.NewPointsClient(conn)` and collections client `qdrant.NewCollectionsClient(conn)`.
5. Check if collection `"stockmind_knowledge"` exists using `collectionsClient.Get`.
6. If it errors because the collection doesn't exist (e.g., check error message or grdc Status), call `collectionsClient.Create` with:
   - `CollectionName: "stockmind_knowledge"`
   - `VectorsConfig` mapped with `Size: 2048` and `Distance: qdrant.Distance_Cosine`.
7. Log success "Qdrant collection ready: stockmind_knowledge".
</action>

<acceptance_criteria>
- File `internal/rag/client.go` exists and is package `rag`
- The file imports `github.com/qdrant/go-client/qdrant` and `github.com/sethvargo/go-retry`
- `InitQdrant` function correctly parses grpc endpoint, connects, and checks collection
- Re-running `InitQdrant` is idempotent (it doesn't wipe an existing collection)
</acceptance_criteria>

### Task 3: Call Qdrant Init from `cmd/main.go`

<action>
In `cmd/main.go`, during the server init (before the router begins accepting traffic), retrieve env vars `QDRANT_HOST` (default `localhost`) and `QDRANT_PORT` (default `6334`).
Call `rag.InitQdrant(ctx, qdrantHost, qdrantPort)`. 
If it returns an error and exceeds retries, log the fatal error and crash the app (it must crash if RAG vector DB is unreachable, or handle it gracefully depending on architecture—but log loud). Let's log a fatal error for now since the milestone is explicitly adding this requirement.
</action>

<acceptance_criteria>
- `cmd/main.go` calls `rag.InitQdrant(ctx, config.QdrantHost, config.QdrantPort)` (or reads from `os.Getenv`)
- The server fails to start if connection continually fails
</acceptance_criteria>
